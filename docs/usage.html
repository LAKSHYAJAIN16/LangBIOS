Documentation

Everything you need to install, build, and use LangBIOS against real firmware.

1. Install

git clone https://github.com/LAKSHYAJAIN16/LangBIOS.git
cd LangBIOS

The native layer that actually talks to firmware needs a separate build step, below. LangBIOS won't do anything useful until that's built.

2. Build the native layer

This compiles native/ (C++) into a shared library Python loads via ctypes, plus a standalone native CLI.

Windows

Requires a C++20 compiler (clang++/LLVM or MSVC) with the Windows SDK.

powershell -ExecutionPolicy Bypass -File native/build.ps1

Produces native/build/langbios_native.dll and native/build/langbios_cli.exe.

The DLL is cross-compiled to match your system Python's architecture: ctypes requires an exact match. If your Python isn't x86_64, edit the --target flag near the top of build.ps1. The standalone CLI always targets your host's real architecture.

Linux

Requires g++ or clang++ with C++20 support.

./native/build.sh

Produces native/build/langbios_native.so and native/build/langbios_cli.

Honesty note: the Linux backend was written against the documented kernel ABIs (efivarfs, /sys/class/firmware-attributes, /sys/class/tpm) but developed on Windows, with no Linux hardware in that environment to verify it against real firmware yet. The Windows backend has been verified end-to-end against real hardware. Test the Linux write path carefully, starting with read-only commands.

3. Run it

# One-shot
python -m langbios.cli "list settings"
python -m langbios.cli "enable secure boot"

# Interactive REPL
python -m langbios.cli

Inside the REPL, type exit or quit to leave. Use --no-llm to disable the local-LLM fallback and only use the fast rule-based parser.

You can also use the standalone native binary directly, without Python:

# Windows
native\build\langbios_cli.exe "list settings"

# Linux
./native/build/langbios_cli "list settings"

4. Example commands

list settings
what's my secure boot
enable secure boot
disable virtualization
what's my fan profile
set fan profile to silent
set power profile to performance
what's my boot order
set boot order to Windows Boot Manager, USB Storage, Internal Storage
reset to factory defaults

Boot order values must match your machine's actual boot entry names (run what's my boot order first to see them). Generic categories like "ssd"/"hdd" won't match anything real.

5. What's actually possible on your hardware

SettingMechanismWritable?Works on
boot_orderStandard UEFI variablesYesAny UEFI machine (elevated)
secure_bootStandard UEFI variableNo, firmware-enforcedAny UEFI machine (elevated, read-only)
tpmWMI / sysfsNo, not OS-writable anywhereAny machine with a TPM (elevated)
virtualization, fan_profile, power_profile, cpu_turbo, fast_boot, xmpVendor WMI (Windows) / firmware-attributes (Linux)Yes, if the vendor stack is presentDell / HP / Lenovo only

On anything else, LangBIOS reports "no vendor BIOS management interface available" rather than pretending a setting changed.

6. Elevation / permissions

  • Windows: needs SeSystemEnvironmentPrivilege, only ever granted to Administrators. Run from an elevated terminal, or enable sudo under Settings → Privacy & Security → For developers.
  • Linux: needs root / CAP_SYS_ADMIN. Run with sudo.

Non-elevated runs still work and explain exactly why an operation needs elevation, instead of failing silently.

7. Local LLM fallback (optional)

For phrasing the rule parser doesn't recognize:

ollama pull llama3.2
ollama serve

Configure via environment variables if needed:

LANGBIOS_OLLAMA_URL=http://localhost:11434
LANGBIOS_OLLAMA_MODEL=llama3.2
LANGBIOS_OLLAMA_TIMEOUT=10

8. Safety notes

  • Boot order writes refuse partial reorders. Every current entry must be listed, in order, so a typo can't silently drop a boot device.
  • Secure Boot and TPM are always read-only from every code path, by firmware design.
  • Vendor attribute writes may only take effect after a reboot / pending-changes commit, and can fail if a BIOS admin password is set; both are reported explicitly.

9. Troubleshooting

"Native library not found": you haven't run the build script yet, or built it for the wrong architecture. See step 2.

"This process's token does not hold SeSystemEnvironmentPrivilege" / "requires running as root": expected outside an elevated/root shell. Re-run elevated.

"No vendor BIOS management interface available": your machine isn't Dell/HP/Lenovo (or the Linux driver isn't loaded). This is a real hardware limitation, not a bug.
